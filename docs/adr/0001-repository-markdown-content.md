# Use repository Markdown as the content source

For the MVP, Blog, AI, and Project content will be maintained as Markdown files in the repository and rendered by the site. This keeps writing close to the engineering workflow, supports version history and review, and avoids the account, deployment, and schema overhead of introducing a Headless CMS before the content model is proven; a CMS can be added later if direct editing or collaboration becomes a real need.

**Status**: accepted

**Considered Options**: Headless CMS; content embedded in JSON or TypeScript.
